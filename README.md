# Duet

설계 캔버스와 코드 리뷰를 한 화면에 두고 터미널의 Claude Code와 함께 쓰는 로컬 협업 도구다. 에이전트는 사람이 띄운 Claude Code 터미널이다(아래 '터미널에서'). Duet은 지도와 리뷰를 보여 주고, 사람이 화면에서 쓴 것을 그 터미널로 보낸다. 브라우저는 `127.0.0.1`에서만 열린다.

## 설치

macOS에서 Node 20.19 이상(22는 22.12 이상), git, Claude Code 2.1.287 이상이 필요하다. 리뷰의 PR은 쓰는 쪽의 `gh`, `glab`, `az`가 있어야 보인다.

```bash
git clone https://github.com/heeseon87/duet.git ~/github/duet
cd ~/github/duet && npm install
ln -s ~/github/duet/bin/duet.mjs ~/.local/bin/duet    # ~/.local/bin이 PATH에 있어야 한다
```

첫 `duet`이 웹 화면을 빌드하므로 개발 의존성까지 설치한다(`npm install --omit=dev`로는 빌드하지 못한다). 업데이트는 `git pull` 뒤 `duet`이다. 실행기가 웹을 다시 빌드하고, 터미널이 처리 중인 메시지가 없으면 서버를 다시 띄운다.

터미널 mod(아래 '터미널에서')는 Claude Code 안에서 유미 마켓플레이스로 설치한다.

```
/plugin marketplace add heeseon87/yuumi
/plugin install duet@yuumi
```

mod는 설치만으로는 도구를 등록하지 않는다. Claude Code를 새로 띄울 때마다 `/duet`을 한 번 쳐야 `duet_map_*` 도구가 생긴다(아래 '연결(`/duet`)'). 치기 전에 지도를 그려 달라고 하면 모델은 그 도구를 찾지 못한다. `/duet` 자체가 없는 명령이라고 나오면 mod가 로드되지 않은 것이므로 `/plugins`의 Errors와 Claude Code 버전(2.1.287 이상)을 확인한다.

## 실행

```bash
duet              # 지금 폴더(git 저장소)를 연다
duet ~/repo       # 다른 저장소를 연다
duet --status     # 서버 상태
duet --stop       # 서버 멈춤 (연결된 터미널은 서버가 돌아오면 다시 붙는다)
duet --no-open    # 브라우저 대신 주소만 출력
```

`duet`은 `~/.local/bin/duet` → `bin/duet.mjs` 심링크다. 서버가 없으면 띄우고, 웹 빌드가 오래됐으면 다시 빌드하고, 서버 코드가 바뀌었으면 (터미널이 처리 중인 메시지가 없을 때) 다시 띄운다. 기본 포트는 7979다.

## 화면

| 영역 | 하는 일 |
|---|---|
| 레일 (왼쪽 끝) | 위에서부터 지도(`⌘1`), 리뷰(`⌘2`, 바뀐 파일 수와 보내기 전 코멘트 수), 결정, 터미널 칸이 있다. 결정은 지금 지도의 결정 모드를 어느 화면에서든 연다: 남은 결정 수가 배지로 붙고, 다 정했으면 정한 결정을 다시 보여 주며, 결정 모드가 열려 있을 때 누르면 닫는다. 지도에 결정이 없거나 옛 rev를 보는 동안은 흐리게 눌리지 않는다. 터미널 칸은 보낼 터미널을 보여 준다: 그 터미널이 질문의 답이나 승인을 기다리면 '대기'(노란 테두리가 흐려졌다 짙어진다), 턴이 돌면 '작업'(테두리가 돈다), 쉬면 '터미널', 터미널이 여럿인데 고르지 않았으면 '고르기', 연결된 터미널이 없으면 '없음'. 턴은 사람이 터미널에 직접 친 것도 mod가 알려 온다. 마우스를 올리면 그 터미널이 지금 하는 일(기다리는 것, 아니면 마지막으로 한 말)이 나온다. 누르면 레일 옆에 터미널 목록이 뜬다. 터미널마다 이름 아래에 일하는 중·쉬는 중과 고정된 지도, 그다음 줄에 지금 하는 일이 나오고(기다리면 노란 글씨), 고르면 그 터미널로 보내고 그 터미널에 고정된 지도가 있으면 연다. 터미널이 하나뿐이면 고르지 않아도 그 터미널로 간다. 아래쪽에는 찾기(`⌘K`), 단축키(`?`), 테마가 있고, 서버와 연결이 끊기거나 서버를 다시 띄워야 하면 그 위에 노란 표시('끊김', '재시작')가 뜬다. 작업 공간 메뉴는 지도와 리뷰의 머리 줄 맨 앞에 있다 |
| 입력창 (지도 위) | 지도 왼쪽 아래(배율 막대 옆, 자리가 좁으면 그 위)에 떠 있다. 쓴 말은 레일의 터미널 칸에서 고른 터미널로 가고, `@`로 파일을 붙인다. 머리 줄에는 그 터미널의 이름(일하는 중이면 에이전트 색)과 그 터미널이 지금 하는 일이 나온다: 터미널에서 질문이나 승인을 기다리면 노란 글씨로 '터미널에서 답을 기다려 · <질문>'이나 '터미널에서 승인을 기다려 · <도구 · 명령이나 파일>', 아니면 메인 에이전트가 마지막으로 한 말(한 줄로 줄여서), 아직 한 말이 없으면 '일하는 중'·'쉬는 중'. 연결된 터미널이 없으면 '터미널 없음'과 `/duet`을 켜라는 말이 나온다. 터미널 없이 보내면 거절하고 토스트로 알리며, 쓴 말은 입력창에 남는다. 에이전트가 일하는 과정과 답은 그 터미널에서 본다. 머리 줄 오른쪽 버튼으로 입력창을 숨기면 새로 고쳐도 숨은 채로 있고, `⌘L`을 누르면 다시 떠서 바로 입력할 수 있다. 쓰던 말과 붙인 파일은 입력창이 잠시 사라져도 남는다. 결정 모드가 열려 있는 동안, 지도가 없을 때, 리뷰에서는 뜨지 않는다 |
| 리뷰 (`⌘2`) | 맨 위 한 줄에 작업 공간 메뉴, 무엇을 보는지를 말하는 제목(지도와 묶였으면 '<지도>의 코드', 아니면 '<저장소>의 변경'), 비교하는 두 쪽, 파일 수, 더하고 뺀 줄, viewed, 코멘트(보내기 전 수)와 경로 복사가 차례로 있다. 폭이 좁으면 제목 뒤의 내용이 둘째 줄로 내려간다. 그 아래 탭이 모드다. 단축키는 `?`로 본다. Changes, Compare(base ← compare, Working tree 포함), Commits(하나 또는 범위), PR(GitHub `gh`, GitLab `glab`, Azure DevOps `az`). 워크트리 선택, 지도가 가리키는 다른 저장소(작업 공간 아래 워크트리나 옆 저장소) 선택. 다른 저장소를 고르면 작업 공간마다 기억한다. 파일 목록은 '지도'로 바꾸면 지금 지도의 패키지 › 상자 › 파일로 묶이고(상자가 가리키지 않는 파일은 '지도 밖'), 캔버스에서 패키지나 상자를 우클릭해 '이 부분의 변경 보기'를 누르면 그 파일들만 본다(코드와 묶이지 않은 지도면 그 코드가 있는 저장소로 옮겨 간다. 아래 '지도와 코드'). Unified/Split 보기, 단어 단위 변경, 문맥 펼치기, 파일 안 찾기(`/`, `⌘F`), Viewed 표시, 방금 바뀐 파일 표시, 줄·범위 코멘트를 모아 한 번에 터미널로 보내기, View file, 마크다운 Preview. 긴 줄은 파일 전체가 한 번에 가로로 움직이고 줄 번호는 제자리에 있다 |
| 캔버스 (`⌘1`) | 터미널의 Claude Code가 mod 도구(`duet_map_*`)로 그리는 클래스·시퀀스 지도. 맨 위 한 줄에 작업 공간 메뉴, 지도 고르기(지도 제목), rev와 마지막으로 고친 쪽, 결정 칩, 코드 칩이 차례로 있고 오른쪽 끝에 지도 동작 아이콘이 있다. 폭이 줄면 덜 중요한 부분(브랜치, 고친 쪽과 시각, '너를 기다림')부터 빠지고, 더 좁으면 제목 뒤의 내용이 둘째 줄로 내려간다. 클래스 지도의 선은 UML대로 그린다: 연관은 실선과 열린 화살표, 의존은 점선과 열린 화살표, 일반화(상속)는 실선과 빈 삼각형, 실체화(구현)는 점선과 빈 삼각형, 집합은 빈 마름모, 합성은 채운 마름모다. 집합·합성은 `from`이 전체라서 마름모가 `from` 쪽에 붙는다. 에이전트는 선의 종류를 두 상자를 잇는 코드로 고르고, 그 코드를 관계의 `via`에 남긴다(`field userRepository`, `param request`, `extends AuditEntity`). 필드로 갖고 있으면 생성자로 주입받은 협력 객체나 enum 필드라도 연관(전체와 부분이면 집합·합성)이고, 매개변수·지역 변수·반환 타입·정적 호출·만들고 버리는 객체·던지는 예외로만 닿으면 의존이며, 클래스가 아닌 상자(액터, 테이블, 엔드포인트)와 잇는 선도 의존이다. 이 기준은 범례의 이름·뜻과 함께 `shared/canvas.ts`(`ARROW_TERMS`, `RELATION_RULES`)에 있고, 도구의 `kind` 설명이 여기서 나온다. 에이전트가 보낸 선의 `via` 첫 단어가 다른 종류의 근거이면(필드인데 의존이면) `canvas_update`는 선을 그대로 그리고, 그 선을 지우고 맞는 종류로 다시 그리라는 note를 결과에 붙인다. 상자나 선을 고르면 이어진 선은 선택 색의 점선이 되어 `from`에서 `to` 쪽으로 흐른다. 고른 상자는 제 모양을 그대로 두고, 테두리에서 조금 떨어진 선택 색 링이 둘린다(배율과 상관없이 2px). 화살촉·삼각형·마름모는 늘 그 선의 색을 따른다. 상자는 카드처럼 그린다: 이름(굵은 본문 글꼴), 멤버, 코드 줄이 왼쪽에 붙어 상자 가운데에 한 덩어리로 모이고, 구분선과 그림자는 없다. 클래스 지도의 멤버, 관계 라벨, 패키지 제목은 고정폭 글꼴이고, 지도 바탕은 점 없이 민무늬다. 상자는 면 색으로 계획을 보여 준다: 새로(`add`)는 연초록, 고침(`modify`)은 연보라 면이고, 선은 기존 상자와 같은 옅은 회색이다. 지움(`delete`)과 결과(`result`) 상자만 색 있는 선을 쓴다. 범례와 리뷰의 '지도' 묶음도 같은 이름을 쓴다. 지도 오른쪽 위에는 반투명한 범례가 떠서 이 지도에 쓰인 상자 상태, 화살표 종류, 결정 전 표시, 그리고 아래 △를 설명한다. 범례는 흐름 목록 오른쪽 자리를 넘지 않는다: 자리가 모자라면 상자 상태·화살표·그 밖의 표시 묶음 단위로 다음 줄로 내려가고, 한 묶음도 넘치면 그 안에서 줄을 바꾼다. 흐름 목록이 있는데 캔버스가 720px보다 좁으면 숨는다. 화살표는 지도에 그렸는지와 상관없이 그 다이어그램이 그릴 수 있는 종류가 모두 지도와 같은 모양으로 나온다: 클래스 지도는 느슨한 관계부터 연관·의존·일반화(상속)·실체화(구현)·집합·합성, 시퀀스 지도는 호출·응답·비동기다. 용어는 국내 UML 자료에서 흔히 쓰는 이름이고, 마우스를 올리면 UML 이름(Association 등)과 뜻이 나온다. 에이전트가 마지막으로 지도를 고친 rev에서 더하거나 고친 상자에는 오른쪽 위 모서리에 그 rev 번호가 든 △가 에이전트 색으로 붙는다(코멘트 수 배지가 있으면 그 왼쪽에). 뒤이어 사람이 그 상자를 고치거나 rev를 복원하면 그 상자의 △는 빠지고, 결정을 골라도 남는다. 지도를 처음 만든 rev에는 붙이지 않고, 옛 rev를 보는 동안에도 붙지 않는다. 지도를 줄이면 △는 결정 핀처럼 커진다. 관계에 단계 번호가 있으면 선의 라벨 앞에 번호가 테두리 원 안에 나오고, 클래스 지도 왼쪽 위에 반투명한 흐름 목록이 뜬다(아래에 떠 있는 입력창이 있으면 그 위까지만 길어진다). 단계 순서대로 원 안의 번호, `보내는 상자 → 받는 상자`, 고정폭 라벨이 나오고(머리에는 단계 수와 `n · p`), 항목에 마우스를 올리면 그 선이 밝아지고, 누르면 그 선을 고른 뒤 지금 배율 그대로 화면 가운데로 옮긴다(다 들어오지 않으면 들어올 만큼만 줄인다). `n`은 다음 단계로, `p`는 이전 단계로 간다. 목록의 머리를 누르면 접히고, 글자 크기는 코드 칸처럼 머리의 −·+(퍼센트를 누르면 100%)나 목록 위에서 `⌘`+휠로 60~140% 사이에서 바꾼다. 접힘과 크기는 기억된다. 상자·선·메시지를 우클릭해 '에이전트에게 묻기'로 물어보면 스레드로 남고 터미널로 간다. 결정(D1의 선택지)은 사람만 고른다. 에이전트는 결정마다 왜 혼자 정하지 않고 묻는지(`why`)를 한두 문장과 꼬리표로 남긴다. 꼬리표는 관례가 둘 이상인데 어느 쪽인지 정해진 게 없음(`convention`), 이 일 밖에 미침(`scope`: 다른 쪽이 부르는 API, 다른 지도, 공용 코드), 나간 뒤에 되돌리기 어려움(`irreversible`), 사람만 아는 정보에 달림(`context`), 확인할 수 있는 것으로는 선택지의 무게가 같음(`tie`)이다. 맞는 꼬리표가 없으면 결정을 열지 않고 에이전트가 정한 뒤 대화에서 알린다. 확인한 것으로 한쪽이 더 맞으면 그 선택지를 `recommended`로 남기고('Claude 추천'), 무게가 같으면 남기지 않는다. 그래도 고르는 것은 사람이다. `why` 없이 열린 결정을 만들면 `canvas_update`가 채우라고 알려 준다. 결정 모드는 질문 바로 아래에 '왜 Claude가 혼자 정하지 않았나'로 이 꼬리표(관례가 둘·이 일 밖에 미침·되돌리기 어려움·네가 아는 것·무게가 비슷)와 이유 문장을 보여 준다(정한 뒤에도). 결정이 모양을 정한 상자와 패키지에는 왼쪽 테두리에 짧은 선으로 이어진 'D3' 원이 붙고(상자는 세로 가운데, 펼친 패키지는 제목 줄 높이에서 여럿이면 위아래로 쌓인다. 결정 전은 보라, 정한 뒤는 초록, 접힌 패키지는 안에 있는 핀을 모아서), 핀을 누르면 그 결정이 만든 부분만 밝아지고 나머지는 물러난다. 지도 제목 뒤에는 정한 수와 전체 수가 나온다(예: 결정 2/9, 남은 결정이 있으면 '너를 기다림'이 붙는다). 칩을 누르면 결정 모드가 캔버스를 덮고 열린 결정을 하나씩 보여 준다. 왼쪽은 결정 목록과 진행 막대, 가운데는 질문과 '왜 Claude가 혼자 정하지 않았나', 선택지 카드(선택지가 둘이면 나란히)다. Claude가 추천한 선택지는 처음부터 골라져 있다. `1`·`2`·`3`으로 고르고 `⏎`(또는 '고른 이유' 칸에서 `⏎`)로 정하면 지도에 바로 반영되고 다음 결정으로 넘어간다. `l`은 나중에(다른 결정을 다 본 뒤 돌아온다), `q`는 고른 선택지에 대해 그 자리에서 묻기(선택지 id `D1-b`의 스레드로 남고 터미널로 간다), `esc`는 결정 모드만 닫는다. 한글 입력 상태에서도 같은 키가 듣는다. 결정 모드가 열려 있는 동안 캔버스 단축키는 듣지 않는다. 정하고 나면 아래에 'D1을 a로 정했어 · 되돌리기'가 8초 동안 뜬다. 되돌리기는 정하기 직전 rev로 복원해서 다른 선택지의 상자까지 돌아오고, 그 사이에 다른 rev가 생겼으면 되돌리지 않고 다시 열기를 권한다. 'Claude에게 보내기'가 켜져 있으면 정한 결정은 바로 보내지 않고 모아 두었다가, 마지막 결정을 정하고 되돌리기가 사라질 때나 결정 모드를 닫을 때 한 프롬프트로 함께 보낸다(`POST /api/canvas/:name/decided`, 각 결정의 스레드에 같은 메시지로 남는다). 모아 둔 결정은 탭을 새로 고치거나 닫아도 남아서, 그 지도를 다시 열 때 보낸다. 보낼 터미널이 없으면 보내지 않고 모아 둔 채 토스트로 알린다. 보내기 전에 다시 연 결정은 빠진다. 다 정하면 요약에서 결정마다 고른 답과 이유, 다시 열기, Claude가 어디쯤인지를 보여 준다. 오른쪽 칸은 지도와 코드 탭이다. 지도 탭은 고른 선택지가 만드는 곳만 밝힌 작은 지도이고(그 선택지만의 상자로 옮겨 간다), 코드 탭은 그 상자들의 `files`가 가리키는 실제 코드를 파일마다 잘라 보여 준다(`path:12-30`은 그 줄 앞뒤, 아니면 선언 줄부터). a·b·c 단추로 선택지를 바꿔 보고, 다 정하면 정한 결정으로 바뀔 파일 목록이 나온다. 왼쪽 결정 목록과 오른쪽 칸은 경계를 끌어 폭을 바꾸고(가운데 결정 칸은 360px보다 좁아지지 않는다), 바꾼 폭은 기억되며 경계를 더블클릭하면 처음 폭으로 돌아간다. 캔버스가 1080px보다 좁으면 결정 목록이, 720px보다 좁으면 오른쪽 칸도 숨는다. 미리 보는 옛 rev에서는 칩을 누를 수 없다. 에이전트에게 보낸 코멘트와 결정에는 지금 어디쯤인지(대기열 몇 번째, 작업 중, 답함, 끝남 · 답 없음)가 스레드 아래 한 줄로 보인다. 모든 수정은 rev로 남아 비교(사라진 것은 흔적으로)·복원이 된다. 펼친 패키지는 테두리 없는 옅은 면으로 그리고, 패키지 안의 패키지는 한 단계마다 지도 바탕색과 번갈아 칠해서 층이 보이게 한다. 접힌 패키지는 같은 면 색에 점선 테두리를 두른 상자다. 펼친 패키지의 제목은 패키지 이름(`label`)이고 면 안쪽 왼쪽 위에 고정폭 글꼴로 쓰이며, 접기 버튼까지 닿을 만큼 길면 말줄임(…)되며 마우스를 올리면 전체 이름이 보인다(제목 위를 지나는 선이 있어도). 상자나 패키지를 더블클릭하면 그 부분이 화면 가운데로 확대된다. 접을 수 있는 패키지에는 접기·펼치기 버튼이 늘 붙어 있다. 펼친 패키지는 제목 줄의 오른쪽 끝에, 접힌 패키지는 상자 위 테두리의 오른쪽에 있다. 버튼은 지도를 줄이면 함께 작아지다가(100%에서 22px) 약 34%보다 작게 보면 사라지고, 화면에서 버튼을 담지 못할 만큼 작아진 패키지에도 없다. 'Collapse all·Expand all'은 한꺼번에 접고 편다. 접고 펴는 동안 상자들이 제자리를 찾아 움직인다. 패키지 하나를 접거나 펴면 그 패키지의 오른쪽 위 모서리(접기 버튼 자리)가 화면에서 그대로 있어서 버튼을 연달아 눌러도 마우스를 옮길 필요가 없다. 펼친 패키지가 캔버스 밖으로 나가면 다 들어올 만큼만 지도를 옮긴다. 캔버스보다 넓거나 높으면 그 방향으로는 옮기지 않고 버튼 자리를 지킨다. 지도를 처음 열면 글자가 읽히는 크기(65% 이상)로 맞추고, 그래도 넘치면 맨 위 가운데부터 보여 준다. 빈 곳이나 선을 더블클릭하면(또는 `f`) 지도 전체가 캔버스에 꽉 차게 맞춰진다. 아무리 큰 지도도 다 들어오도록 필요한 만큼 작아진다. 휠은 확대·축소, `⇧`+휠은 이동. 지도 오른쪽 아래의 배율 막대에는 축소·지금 배율·확대, '맞춤'(`f`), '코드'(`c`)가 있고, 머리 줄 오른쪽에는 Compare with previous, Collapse all·Expand all, 내보내기, 지도 지우기가 아이콘으로 있다. `c`(또는 지도 오른쪽 아래 배율 막대의 '코드')는 캔버스 옆에 코드 칸을 연다: 누른 상자의 파일이 열리고(아직 누른 것이 없거나 그 부분이 지도에서 사라졌으면 칸은 숨어 있다가 누르면 나온다)(파일이 여럿이면 탭, 패키지는 안에 있는 파일, 선은 양 끝 상자의 파일) 클래스 선언 줄이나 `files`에 적은 줄(`path:12-30`)이 표시된다. 칸이 열리고 닫히면 지도는 남은 자리의 가운데로 미끄러져 옮겨 가고, 보이던 누른 상자는 계속 보인다. 경계를 끌 때나 창 크기 때문에 캔버스 폭이 바뀔 때도 지도는 보이던 가운데를 지킨다. 지도가 코드에 묶여 있으면 리뷰가 보여 주는 같은 코드를 읽고, 그 코드에서 더해지거나 바뀐 줄은 줄 번호 옆에 초록 띠가 붙고, 그 수가 칸 머리의 이름 옆에 `+n`으로 나온다. 빈 곳을 누르면 보던 코드가 그대로 남는다. 경계를 끌어 폭을 바꾸고, 코드 글자 크기는 칸 머리 ⋯ 메뉴의 −·+(퍼센트를 누르면 100%)나 칸 위에서 `⌘`+휠(트랙패드는 핀치)로 지도와 따로 바꾼다. 배율을 바꿔도 맨 위에 보이던 줄은 그 자리에 있다. 코드는 편집기처럼 읽는다: 단어를 누르거나 한 줄 안에서 글자를 골라 두면 같은 단어(고른 글자)가 파일 전체에서 강조되고 몇 곳인지가 경로 줄에 나오며, 누른 줄은 옅게 표시된다. 칸 위의 구조 버튼을 켜면 파일의 클래스·함수·필드가 들여쓰기대로 코드 왼쪽에 나열된다(Kotlin, Java, Swift, C#, C·C++, TS·JS, Python, SQL의 표와 열, 마크다운 제목). 생성자에서 선언한 필드(Kotlin 주 생성자의 `val`·`var`, Java record의 요소, C# record와 주 생성자의 매개변수, TS 생성자의 `private`·`readonly` 매개변수)는 본문의 필드와 다른 표시(초록 c)로 나온다. 누른 줄이 속한 선언이 표시되고, 목록에서 하나를 누르면 그 줄로 가서 이름이 강조된다. 목록의 오른쪽 경계를 끌어 폭을 바꾸고, 왼쪽 끝까지 끌어 놓으면 목록이 닫힌다(구조 버튼으로 다시 열면 그 전 폭으로 나온다). 칸이 좁으면 목록이 코드 위에 떴다가 하나를 고르면 닫힌다. 칸 위의 팔레트 버튼(변수 색)을 켜면 Kotlin·Java·TypeScript 파일에서 변수마다 한 색이 칠해지고, 나머지 코드(타입·문자열 등)는 테마 색의 밝기만 남긴 회색 명암으로 낮아진다. 키워드(`val`, `fun`, `private`, `return` 등)만은 변수 색과도 회색과도 겹치지 않는 한 가지 색으로 남는다. 매개변수, 지역 변수, 클래스의 프로퍼티·필드는 선언부터 그것을 가리키는 모든 사용처(`this.x`로 쓴 프로퍼티·필드, Kotlin 문자열 템플릿의 `$name` 포함)까지 같은 색이고, 스코프가 다르면(안쪽에서 같은 이름으로 다시 선언한 변수, 람다 매개변수, Kotlin의 `it`) 다른 변수로 본다. 세 줄 안에서 함께 쓰이는 변수끼리는 색이 겹치지 않게 고르고, 멀리 떨어져 쓰이는 변수끼리는 같은 색을 다시 쓴다(그래프 색칠). 색은 나머지가 회색이 되므로 색상 전체에서, 가장 가까운 두 색이 최대한 멀도록 키워드 색과 함께 테마마다 고른 8색이다. 클래스 프로퍼티·필드는 자기 색에 옅은 점선 밑줄이 더해져서, 같은 색이 된 지역 변수와 구분된다. `a.b`의 멤버, 이름 붙인 인자, 타입, 함수 이름은 칠하지 않는다. tree-sitter로 파일을 파싱하고 `web/src/canvas/locals/*.scm`의 locals 쿼리로 스코프를 풀며, 문법은 처음 켤 때 그 언어 것만 받는다. 열림·폭·배율, 구조와 변수 색을 켰는지, 구조의 폭은 기억된다. 우클릭 메뉴의 '코드 열기'도 이 칸에서 열리고, ⋯ 메뉴에서 경로를 복사하거나 리뷰에서 본다. 지도의 코드에서 바뀐 파일이면 칸 머리에서 이름 옆의 Viewed로 리뷰와 같은 표시를 켜고 끈다. 캔버스는 처음에 코드 칸을 켠 채로 열리며(코드 칸은 상자를 누르면 나온다), 닫으면 그 상태를 기억한다. 우클릭하면 그 부분의 메뉴가 뜬다: 에이전트에게 묻기(그 자리에 바로 입력), 코드 열기, Viewed로 표시(그 부분의 바뀐 파일을 한꺼번에, 다 봤으면 Viewed 해제), Zoom to selection, 패키지는 이것만 펼치기(나머지는 접기). 클래스 지도는 ELK로 그려서, 최상위 패키지의 좌우 순서를 우클릭 '왼쪽으로·오른쪽으로 옮기기'로 정할 수 있다(지도에 rev로 남고, 접고 펴도 유지된다). 패키지 안 상자의 자리는 이어진 선이 정한다. 빈 곳을 우클릭하면 Zoom to fit·Collapse all·Compare with previous 같은 지도 전체 동작이 뜬다. ## 지도와 코드

지도는 자기가 다루는 코드를 안다. 그래서 캔버스와 리뷰가 같은 코드를 보여 준다.

- **설계 먼저.** 지도를 만들면 그 순간의 커밋부터 지금 작업 트리까지(`base...작업 트리`, 커밋 안 한 새 파일 포함)에 묶인다. 터미널은 그 터미널의 폴더, 브라우저는 작업 공간이 기준이다. 지도대로 구현하면 커밋을 했든 안 했든 바로 리뷰에 잡힌다. 아직 커밋이 없는 저장소는 커밋 안 한 변경에 묶인다.
- **리뷰 목적.** `duet_map_create`(`canvas_create`)에 `code`로 `pr`, `pr:123`, `branch:main...feature`, `commits:a..b`를 주면 그 코드에 묶인다. 커밋이나 브랜치가 그 저장소에 없으면 지도를 만들지 않는다. 엉뚱한 저장소에 묶여 리뷰가 비는 일을 막기 위해서다.
- **다른 저장소의 코드.** `repo`에 그 저장소 안의 폴더를 주면, 터미널이 어느 폴더에서 열렸든 그 저장소에 묶인다. 워크트리에서 구현하는 코드라면 그 워크트리를 준다. 커밋 범위는 어느 워크트리에서 보든 같지만, 설계 지도가 따라가는 커밋 안 한 변경은 그 워크트리에만 있기 때문이다. 작업 공간 밖의 저장소에 묶인 지도는 상자 `files`의 상대 경로가 그 저장소 루트에서 시작한다. 그 밖의 지도(작업 공간, 그 안의 워크트리)는 지금처럼 작업 공간에서 시작한다. 도구는 지도를 만들거나 읽을 때 이 기준 폴더를 알려 준다.
- **리뷰는 지도를 따라간다.** 지도가 열려 있는 동안 리뷰는 그 지도의 코드만 보여 주고 비교 대상을 고르는 막대는 '지도 «제목»의 코드'로 바뀐다. 다른 것을 보려면 '코드 기준 바꾸기'를 눌러 고르고 '이 기준으로 저장'(지도의 기준이 바뀐다)하거나 '취소'한다. 다른 선택은 거절하고 토스트로 알린다. 다른 저장소에 있는 상자의 '이 부분의 변경 보기'도 리뷰를 옮기지 않고 그 코드가 지도의 코드 밖이라고 알린다.
- **캔버스는 계획과 실제를 같이 보여 준다.** 상자의 색(새로·고침)은 계획이고, 상자 안 마지막 줄(줄을 넣을 자리가 없는 상자는 아래 테두리 왼쪽의 배지)은 리뷰와 같은 파일로 본 실제다: '코드 n'(파일이 바뀜), '계획 밖 n'(바꾸기로 하지 않은 상자의 파일이 바뀜), '구현 전'(바꾸기로 했는데 아직 그 파일이 안 바뀜). 리뷰에서 그 파일을 모두 Viewed로 표시하면 그 줄 뒤(배지는 앞)에 체크가 붙는다(패키지는 안에 든 상자의 파일까지 센다). Viewed는 캔버스에서도 코드 칸이나 우클릭 메뉴로 바꾼다. 파일이 다시 바뀌어 Viewed가 풀리면 체크도 사라진다. 지도 제목 아래 줄의 칩은 '바뀐 파일 · 구현 전 · 계획 밖 · 지도 밖'을 세고, 누르면 리뷰로 간다. 파일과 상자를 짝짓는 규칙은 리뷰의 '지도' 묶음과 같은 함수(`shared/mapFiles.ts`)다. 그래서 에이전트는 상자를 구현할 때 그 상자의 `files`를 채운다.
- **예전 지도.** 코드와 묶이지 않은 지도는 처음 열 때 한 번 묻는다: '지도가 가리키는 코드에 연결'(상자 `files`가 가장 많은 저장소를, 지도를 만든 때의 커밋부터 지금까지. 그 워크트리가 지워졌으면 작업 공간), 'PR·브랜치·커밋 고르기', '나중에'. 나중에 묶으려면 상단의 '코드 연결' 칩을 누른다.
- 묶음은 지도 파일(`<name>.map.json`의 `code`)에 rev 밖으로 따로 남는다. 그래서 rev 비교·복원과 무관하고, 수정이 쌓여도 유지된다.

## 구조

```
bin/duet.mjs           실행기
server/main.ts         HTTP + SSE, 인증, 라우트
server/agent/          캔버스 도구(설명·스키마·실행)
server/prompt.ts       터미널로 보내는 프롬프트(붙인 것을 한 블록으로)
server/git/            저장소 정보, diff(작업 중·브랜치·커밋·PR), PR(gh)
server/canvas/         지도 저장(rev 기록, 스레드)
server/terminals.ts    터미널 목록, 터미널로 가는 메시지 대기열, 폴더 → 작업 공간 찾기
shared/                프로토콜 타입, 캔버스 모델(검증·패치·diff·Mermaid)
web/src/               React 화면 (agent / review / canvas)
tests/                 vitest 단위 테스트
e2e/browser.mjs        헤드리스 브라우저 도우미
mod/                   터미널 Claude Code용 mod (아래)
scripts/mod-tools.ts   mod/hooks/tools.ts를 캔버스 도구에서 다시 쓴다
```

데이터는 `~/.duet/`에 있다: `canvas/`(지도와 기록), `reviews/`(리뷰 코멘트), `workspaces.json`, `token`, `server.log`. Duet이 직접 대화를 띄우던 때의 `sessions/`는 더 읽지 않는다. 그때 대화로 보낸 코멘트와 결정은 스레드에 '끝남'으로 남는다.

## 터미널에서 (Duet mod)

`mod/`는 Claude Code mod다. 터미널의 Claude Code 세션이 Duet 지도를 만들고 읽고 고치고, Duet에서 보낸 것을 받는다. Duet은 그대로 돈다.

보통은 유미 마켓플레이스에서 설치한다(위 '설치'). 유미는 이 저장소의 `mod/`를 커밋 sha로 고정해 두므로, 받는 쪽은 그 커밋의 mod를 쓴다. 이 체크아웃의 mod를 바로 쓰려면(개발) 다음처럼 띄운다.

```bash
claude --plugin-dir ~/github/duet/mod     # 이 세션에만
```

늘 켜 두려면 다른 로컬 플러그인처럼 `~/.claude/local-plugins/duet` → `~/github/duet/mod` 심링크를 만들고 `CLAUDE_CODE_PLUGIN_DIRS`에 더한다. 어느 쪽이든 Claude Code 2.1.287 이상이 필요하다.

- **도구.** `duet_map_list`, `duet_map_read`, `duet_map_create`, `duet_map_update`, `duet_map_reply`. 설명·스키마는 서버의 `CANVAS_TOOLS`(`canvas_*`)에서 나오고(`npm run mod:tools`로 다시 쓰고, 테스트가 어긋남을 잡는다), 서버의 같은 코드로 돈다. 터미널이 만들거나 고친 rev는 에이전트 것으로 남고 메모 앞에 `터미널 · <폴더> · <세션 id 8자>`가 붙는다. 터미널에는 MCP 서버 지시가 없어서, 지도를 그리는 법은 `duet_map_read`와 `duet_map_create`의 결과 앞에 붙는다.
- **지도 만들기.** `duet_map_create`는 빈 지도를 만들고, 모델은 결과에 붙은 그리는 법을 읽고 바로 `duet_map_update`로 그린다. 폴더가 어느 작업 공간에도 없으면 먼저 그 폴더의 git 저장소를 작업 공간 메뉴에서 연 것처럼 Duet 작업 공간으로 열고, 터미널을 거기에 등록한 뒤 만든다. git 저장소 밖이면 git 저장소가 필요하다고 답하고 아무것도 열지 않는다. 다른 도구는 작업 공간 밖에서 그대로 거절하고, `duet_map_create`로 시작할 수 있다고 알린다.
- **보내기.** 세션은 cwd가 속한 작업 공간(그 폴더를 품은 작업 공간, 아니면 그 저장소를 가리키는 지도가 있는 작업 공간)에 터미널로 등록된다. 레일의 터미널 칸에서 고르면(연결된 터미널이 하나뿐이면 저절로 골라진다) 캔버스 코멘트, 알림을 켠 결정, 리뷰 코멘트, 입력창에 쓴 말이 프롬프트로 그 세션에 간다. 보낼 터미널이 없으면 서버는 스레드나 코멘트에 아무것도 쓰기 전에 거절하고(409), 화면은 토스트로 알린다. 세션이 쉬고 있으면 바로, 일하는 중이면 끝난 뒤 한 턴으로 돈다. 스레드에는 대기열 → 터미널에 전달함 → 작업 중 → 답함이 보이고, 그 턴의 답이 스레드에 달린다. 그 턴이 하위 에이전트를 백그라운드로 띄웠으면 에이전트가 결과를 넘겨 시작된 턴까지 '작업 중'으로 기다렸다가 마지막 턴의 답을 단다("에이전트가 찾는 중" 같은 중간 답은 달지 않는다). 결과가 돌던 턴 안으로 들어가 따로 턴이 없으면, 에이전트가 다 끝나고 세션이 3초 조용할 때 마지막 답을 단다. 닫힌 터미널로 보내면 실패하고 토스트로 알린다.
- **하는 일.** mod는 그 터미널이 하는 일을 `POST /api/terminals/:id/activity`로 알리고, 서버는 `TerminalInfo.activity`에 담아 모든 탭에 보낸다. 마지막 말은 메인 에이전트의 응답 행(`session.append`의 `response`)에 든 글을 한 줄로 줄인 것(200자까지)이고, 도구만 부른 행은 그 전 말을 그대로 둔다. 기다림은 두 가지다. `AskUserQuestion`은 호출부터 답할 때까지 질문으로 알린다. 메인 에이전트의 호출 중 `tool.check`가 `ask`로 판정한 호출은 3초 뒤에도 그대로면 승인으로 알린다(작업 폴더 안의 파일은 상대 경로로): auto 모드의 분류기가 정하는 ask는 사람에게 보이지 않고 대개 1~2.5초 안에 끝나기 때문이다. 호출이 끝나거나, Bash가 백그라운드로 보내기 힌트(`ToolProgress`)를 띄우면(실행이 시작됐다는 뜻) 기다림을 지운다. 턴이 끝나면 서버도 지운다(Esc로 끊긴 경우). mod는 알림과 턴 보고를 앞의 것이 끝난 뒤에 보내므로, 서버에는 보낸 순서대로 닿는다. 한계가 셋 있다. auto 모드에서 분류기가 판정하는 시간과 Bash 힌트가 뜨기까지의 시간을 더해 3초를 넘으면 '대기'가 잠깐 보인다. 승인된 뒤 오래 도는 호출 중 Bash가 아닌 것(느린 MCP 도구 같은)은 끝날 때까지 '대기'로 남는다. 하위 에이전트의 승인은 알리지 않는다: 하위 에이전트의 Bash에는 힌트가 뜨지 않아서, auto 모드에서 분류기가 통과시킨 긴 명령이 끝날 때까지 '대기'로 남기 때문이다. 모두 승인 대화 상자가 떴는지 알려 주는 훅이 없어서 생긴다. 다시 등록해도(지도 고정, 끊긴 poll 뒤) 서버는 하는 일을 지키고, 서버가 새로 뜨면 mod가 연결하면서 다시 알린다.
- **연결(`/duet`).** 세션은 Duet에 붙지 않은 채 시작한다: 폴링도, `duet_map_*` 도구도, 상태 줄도 없다. `/duet`(또는 `/duet <지도>`)을 쳐야 그 터미널이 Duet에 등록되고 도구가 생기며 폴링이 돈다. `/duet off`는 고정을 풀고 연결을 끊는다(Duet 터미널 목록에서 빠지고 상태 줄이 사라진다). `/duet new <이름> [제목]`은 모델 턴 없이 빈 지도를 만든다: 다이어그램 종류(class·sequence)를 물어보고, 만든 지도를 이 터미널에 고정한다. 제목을 안 적으면 이름이 제목이 되고, 대화창을 닫으면 아무것도 만들지 않는다. 그래서 `new`라는 이름의 지도는 `/duet new`로 고정할 수 없다. 이미 등록된 도구는 남지만 다시 연결할 때까지 거절한다.
- **기준 지도(`/duet`).** `/duet <지도>`는 이 터미널이 기준으로 삼을 지도를 고정한다. 지도 이름과 똑같으면 그 지도, 아니면 이름이나 제목에 그 글자가 든 지도가 하나뿐일 때 그 지도다(대소문자 무시). 여럿이거나 없으면 후보(이름 · 제목)를 보여 주고 아무것도 바꾸지 않는다. `/duet`만 치면 고정된 지도(없으면 `고정된 지도 없음`)와 작업 공간의 지도 목록(이름 · 제목 · rev, 결정이 있는 지도는 결정 a/b)을, `/duet off`는 고정을 풀고 연결을 끊는다. 고정은 그 터미널(프로세스)에만 있다: 같은 폴더라도 새 세션은 고정 없이, 연결 없이 시작한다(`/clear` 뒤에는 이어진다). 지도가 지워지면 고정도 풀린다. 고정이 바뀌면 모델은 턴을 새로 열지 않고 듣는다: `/duet`의 답에 붙은 숨은 메모(`command.run`의 `context`)로, `/clear` 뒤에는 보이지 않는 user 행(`$.session.append`)으로. 대화를 압축하면(`/compact`, 자동 압축) 요약이 그 메모를 빠뜨릴 수 있어서, 턴이 시작될 때 모델이 받는 메시지(`$.session.messages({ as: 'api' })`)에 메모가 없으면 같은 행으로 다시 듣는다. `session.compact` 훅은 쓰지 않는다: Team·Enterprise 조직 계정이나 managed settings가 있는 기기에서는 Claude Code 내장 플러그인 `cc-plugin-sec-default`가 가장 바깥에 앉아서, 이 이벤트를 사용자가 설치한 플러그인을 건너 넘긴다. 그래서 이 훅은 돌지 않고 /plugins의 Errors에 올라간다. 관리자가 managed settings의 `prependPlugins`에서 그 플러그인을 빼지 않는 한 사용자가 끌 수 없다. 그래서 지도를 말하지 않은 "이 터미널의 지도"는 `duet_map_*` 도구에 고정된 이름으로 간다. 고정된 지도가 없는 터미널이 `duet_map_create`로 지도를 만들면 `/duet <지도>`처럼 그 지도가 고정되고, 모델은 그 도구 결과로 듣는다. 이미 고정된 지도가 있으면 그대로 두고, 새 지도는 마지막으로 만진 지도가 된다. Duet의 터미널 목록에도 `map`으로 올라가서, 레일의 터미널 목록에 `📌 <제목>`이 보이고 거기서 그 터미널을 고르면 캔버스가 그 지도를 연다.
- **상태 줄.** `Duet · <지도 제목> · rev N · 결정 a/b · 코멘트 n`. 터미널에서는 프롬프트 아래 힌트 줄(`? for shortcuts`) 끝에 흐리게 붙는다(`$.ui.status`로 띄우면 Claude Code가 ⚠ 알림처럼 그려서다). 터미널이 없는 세션(SDK, `-p`)에서는 플러그인 상태 줄(`ui.status`)로 나온다. 고정한 지도가 있으면 늘 그 지도이고 제목 앞에 📌가 붙는다(`Duet · 📌 <지도 제목> · …`). 없으면 이 터미널이 마지막으로 읽거나 고친 지도, 그 뒤에 다른 지도가 바뀌었으면 그 지도. 서버가 없으면 `Duet 꺼짐`, 작업 공간을 못 찾으면 `Duet 작업 공간 없음`이고(`duet_map_create`로 지도를 만들면 그 저장소가 작업 공간이 된다), 서버가 돌아오면 스스로 다시 붙는다.
- **연결.** `$DUET_HOME`(없으면 `~/.duet`)의 `server.json`과 `token`(또는 `DUET_TOKEN`)을 읽는다. mod는 SSE를 읽을 수 없어서(`$.http.fetch`는 본문이 끝나야 돌아온다) `GET /api/terminals/:id/poll`을 길게 붙잡는다. 이 poll이 heartbeat이고, 메시지와 지도 변경을 받는 길이다.
- `DUET_CONVERSATION=1`인 세션에서는 mod가 아무것도 안 한다. Duet이 직접 대화를 띄우던 때의 장치다.
- `npm run typecheck`는 `mod/.claude-plugin/types/`를 읽는다. Claude Code가 `--plugin-dir`로 mod를 띄울 때 그 버전의 타입을 거기 쓴다.

## 지켜야 할 것

- 서버는 Bash를 돌리는 터미널 에이전트에게 프롬프트를 보내므로, `127.0.0.1`에만 묶고 토큰 쿠키, Host·Origin 검사를 둔다. CORS는 열지 않는다.
- 리뷰와 스냅샷은 작업 트리, 진짜 인덱스, stash를 건드리지 않는다. 스냅샷은 임시 인덱스로 트리 객체만 만든다.
- 지도와 리뷰 머리 줄 맨 앞의 작업 공간 메뉴에서 최근 작업 공간, 이 저장소의 워크트리, 홈 아래 세 단계 안의 저장소를 이름으로 찾아 연다. `~/`부터 입력하면 폴더를 한 단계씩 들어간다(`Tab`).
