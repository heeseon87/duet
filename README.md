# Duet

설계 캔버스, 코드 리뷰, 실시간 에이전트를 한 화면에 둔 로컬 협업 도구다. 에이전트는 이 컴퓨터의 Claude Code(Agent SDK)로 돌고, 브라우저는 `127.0.0.1`에서만 열린다.

## 실행

```bash
duet              # 지금 폴더(git 저장소)를 연다
duet ~/repo       # 다른 저장소를 연다
duet --status     # 서버 상태
duet --stop       # 서버 멈춤 (대화는 다음 프롬프트에 이어진다)
duet --no-open    # 브라우저 대신 주소만 출력
```

`duet`은 `~/.local/bin/duet` → `bin/duet.mjs` 심링크다. 서버가 없으면 띄우고, 웹 빌드가 오래됐으면 다시 빌드하고, 서버 코드가 바뀌었으면 (일하는 대화가 없을 때) 다시 띄운다. 기본 포트는 7979다.

처음 한 번은 의존성을 설치한다.

```bash
cd ~/github/duet && npm install
```

## 화면

| 영역 | 하는 일 |
|---|---|
| 에이전트 패널 (오른쪽) | 답, 생각 요약, 도구 호출이 스트리밍으로 쌓인다. Bash 출력, Edit diff, 하위 에이전트 중첩, 연달은 생각·탐색·셸 명령은 Claude Code처럼 한 줄로 접힘("Thought for 7s, read 1 file, ran 2 shell commands"), 수정은 "Added n lines, removed m lines"와 바뀐 단어가 표시된 diff, 새 파일은 앞 10줄 미리보기, 승인 카드(Allow·Always allow·Deny), 질문과 계획 승인, 중단(esc), 대기열, `@파일` 붙이기, 스크린샷 붙여넣기·끌어다 놓기, 턴마다 걸린 시간과 바뀐 파일 수("파일 2개 +12 −3"). 포커스(`⌘.`)를 켜면 턴이 Claude Code처럼 타임라인으로 보인다: 에이전트가 중간중간 한 말과 나를 기다리는 카드는 그대로, 그 사이 도구 호출은 "Read 2 files, ran 1 shell command"처럼 한 문장으로 집계되고 지금 실행 중인 호출만 따로 한 줄로 보인다(끝나면 집계에 합류). 긴 답과 대화 요약은 왼쪽에 넓게 펼쳐 읽는다(목차, `[` `]`로 앞뒤 답, `esc`로 닫기). 입력창 위 상태 줄은 나를 기다리는 것을 종류별로 센다("질문 1개 · 답하기", 누르면 그 카드로). 기다리는 게 없으면 에이전트가 이 턴에서 마지막으로 한 말을 보여 준다(누르면 그 자리로, 지금 하는 일은 툴팁). 기다리는 카드에는 노란 테두리가 둘리고, 답한 질문은 고른 답만 남기고 나머지 선택지는 접는다. 컨텍스트 계기판은 메인 에이전트의 마지막 호출이 읽은 양을 모델 창 대비 %로 보여 주고, 80%를 넘으면 노랗게 바뀐다. 다른 탭에 있으면 입력 대기나 끝남을 탭 제목으로 알린다 |
| 리뷰 (`⌘2`) | Changes, Compare(base ← compare, Working tree 포함), Commits(하나 또는 범위), Turns, PR(GitHub `gh`, GitLab `glab`, Azure DevOps `az`). 워크트리 선택, 대화가 고친 다른 저장소(작업 공간 아래 워크트리나 옆 저장소) 선택: 에이전트가 거기에 쓰면 턴마다 그 저장소의 전후 스냅샷을 남겨서 'Turns'로도 보이고, 작업 공간을 보는 중이면 위에 안내가 뜬다. 리뷰는 지금 대화가 일하는 저장소(파일을 바꾼 마지막 턴이 가장 많이 바꾼 곳)에서 열리고, 그 저장소는 상단에 칩으로 보인다. 다른 저장소를 고르면 대화마다 기억한다. '파일을 바꾼 마지막 턴'은 아무것도 바꾸지 않은 뒤 턴을 건너뛴다. Compare의 base로 '턴 시작 직전 커밋'을 고를 수 있고(reflog로 찾는다), 저장소별 스냅샷이 없는 옛 턴은 이걸로 추정해서 보여 준다. 파일 목록은 '지도'로 바꾸면 지금 지도의 패키지 › 상자 › 파일로 묶이고(상자가 가리키지 않는 파일은 '지도 밖'), 캔버스에서 패키지나 상자를 우클릭해 '이 부분의 변경 보기'를 누르면 그 파일들만 본다(코드와 묶이지 않은 지도면 그 코드가 있는 저장소로 옮겨 간다. 아래 '지도와 코드'). Unified/Split 보기, 단어 단위 변경, 문맥 펼치기, 파일 안 찾기(`/`, `⌘F`), Viewed 표시, 방금 바뀐 파일 표시, 줄·범위 코멘트를 모아 한 번에 에이전트에게 보내기, View file, 마크다운 Preview. 긴 줄은 파일 전체가 한 번에 가로로 움직이고 줄 번호는 제자리에 있다 |
| 캔버스 (`⌘1`) | 에이전트가 MCP 도구(`mcp__duet__canvas_*`)로 그리는 클래스·시퀀스 지도. 상자·선·메시지를 눌러 물어보면 스레드로 남고 대화로 간다. 이름·상태·메모·관계 라벨·단계는 사람이 그 자리에서 고치고 지울 수도 있다. 결정(D1의 선택지)은 사람만 고른다. 결정이 모양을 정한 상자와 패키지에는 'D3' 핀이 붙고(결정 전은 보라, 정한 뒤는 초록, 접힌 패키지는 안에 있는 핀을 모아서), 핀이나 결정 카드의 번호를 누르면 그 결정이 만든 부분만 밝아지고 나머지는 물러난다. 정한 결정은 한 줄씩 접혀 있다가 누르면 이유와 버린 선택지까지 펼쳐지고, 상단 칩에는 정한 수와 전체 수가 나온다(예: 결정 2/9). 에이전트에게 보낸 코멘트와 결정에는 지금 어디쯤인지(대기열 몇 번째, 작업 중, 답함, 끝남 · 답 없음)가 스레드 아래 한 줄로 보인다. 모든 수정은 rev로 남아 비교(사라진 것은 흔적으로)·복원이 된다. 패키지는 더블클릭이나 'Collapse all·Expand all'로 접고 펴며, 바뀌는 동안 상자들이 제자리를 찾아 움직인다. 빈 곳을 더블클릭하면(또는 `f`) 지도 전체가 캔버스에 꽉 차게 맞춰진다. 아무리 큰 지도도 다 들어오도록 필요한 만큼 작아진다. 휠은 확대·축소, `⇧`+휠은 이동. 탐색 모드(`e`)에서는 눌러도 정보 카드가 열리지 않고 강조만 된다(카드는 `i`로 직접 연다). 우클릭하면 그 부분의 메뉴가 뜬다: 에이전트에게 묻기(그 자리에 바로 입력), 코드 열기, Zoom to selection, 패키지는 이것만 펼치기(나머지는 접기). 클래스 지도는 ELK로 그려서, 최상위 패키지의 좌우 순서를 우클릭 '왼쪽으로·오른쪽으로 옮기기'로 정할 수 있다(지도에 rev로 남고, 접고 펴도 유지된다). 패키지 안 상자의 자리는 이어진 선이 정한다. 빈 곳을 우클릭하면 Zoom to fit·Collapse all·탐색 모드·Compare with previous 같은 지도 전체 동작이 뜬다. Mermaid 복사, 지금 색 그대로 SVG 저장 |
| 명령 팔레트 (`⌘K`) | 명령, 파일 열기, 입력하는 동안 코드 검색(전체는 `⇧⏎`), 지도·대화 전환 |
| 테마 | 화면 시스템/밝게/어둡게, 코드 색 팔레트 18가지(밝은·어두운 짝). `?`로 단축키 전체 |

리뷰 단축키: `j`/`k` 파일, `n`/`p` hunk, `v` Viewed, `u`/`s` Unified·Split, `w` Hide whitespace changes 켜고 끄기(기본은 켜짐), `/` 찾기, `m` 코멘트 탭, `r` Refresh. 전체 목록은 `?`.

## 지도와 코드

지도는 자기가 다루는 코드를 안다. 그래서 캔버스와 리뷰가 같은 코드를 보여 준다.

- **설계 먼저.** 지도를 만들면 그 순간의 커밋부터 지금 작업 트리까지(`base...작업 트리`, 커밋 안 한 새 파일 포함)에 묶인다. 터미널은 그 터미널의 폴더, Duet 대화는 대화가 일하는 저장소, 브라우저는 작업 공간이 기준이다. 지도대로 구현하면 커밋을 했든 안 했든 바로 리뷰에 잡힌다. 아직 커밋이 없는 저장소는 커밋 안 한 변경에 묶인다.
- **리뷰 목적.** `duet_map_create`(`canvas_create`)에 `code`로 `pr`, `pr:123`, `branch:main...feature`, `commits:a..b`를 주면 그 코드에 묶인다.
- **리뷰는 지도를 따라간다.** 지도가 열려 있는 동안 리뷰는 그 지도의 코드만 보여 주고 비교 대상을 고르는 막대는 '지도 «제목»의 코드'로 바뀐다. 다른 것을 보려면 '코드 기준 바꾸기'를 눌러 고르고 '이 기준으로 저장'(지도의 기준이 바뀐다)하거나 '취소'한다. 한 턴은 지도의 기준이 될 수 없다. 지도가 열려 있는 동안 Turns 같은 다른 선택은 거절하고 토스트로 알린다. 다른 저장소에 있는 상자의 '이 부분의 변경 보기'도 리뷰를 옮기지 않고 그 코드가 지도의 코드 밖이라고 알린다.
- **캔버스는 계획과 실제를 같이 보여 준다.** 상자의 색(New·Modified)은 계획이고, 아래 왼쪽 배지는 리뷰와 같은 파일로 본 실제다: '코드 n'(파일이 바뀜), '계획 밖 n'(바꾸기로 하지 않은 상자의 파일이 바뀜), '구현 전'(바꾸기로 했는데 아직 그 파일이 안 바뀜). 상단 칩은 '바뀐 파일 · 구현 전 · 계획 밖 · 지도 밖'을 세고, 누르면 리뷰로 간다. 파일과 상자를 짝짓는 규칙은 리뷰의 '지도' 묶음과 같은 함수(`shared/mapFiles.ts`)다. 그래서 에이전트는 상자를 구현할 때 그 상자의 `files`를 채운다.
- **예전 지도.** 코드와 묶이지 않은 지도는 처음 열 때 한 번 묻는다: '지도가 가리키는 코드에 연결'(상자 `files`가 가장 많은 저장소를, 지도를 만든 때의 커밋부터 지금까지. 그 워크트리가 지워졌으면 작업 공간), 'PR·브랜치·커밋 고르기', '나중에'. 나중에 묶으려면 상단의 '코드 연결' 칩을 누른다.
- 묶음은 지도 파일(`<name>.map.json`의 `code`)에 rev 밖으로 따로 남는다. 그래서 rev 비교·복원과 무관하고, 수정이 쌓여도 유지된다.

## 구조

```
bin/duet.mjs           실행기
server/main.ts         HTTP + SSE, 인증, 라우트
server/agent/          Agent SDK 세션(스트리밍 입력, 권한, 턴 스냅샷), 캔버스 MCP 도구
server/git/            저장소 정보, diff(작업 중·브랜치·커밋·턴·PR), PR(gh)
server/canvas/         지도 저장(rev 기록, 스레드)
server/terminals.ts    터미널 목록, 터미널로 가는 메시지 대기열, 폴더 → 작업 공간 찾기
shared/                프로토콜 타입, 캔버스 모델(검증·패치·diff·Mermaid)
web/src/               React 화면 (agent / review / canvas)
tests/                 vitest 단위 테스트
e2e/browser.mjs        헤드리스 브라우저 도우미
mod/                   터미널 Claude Code용 mod (아래)
scripts/mod-tools.ts   mod/hooks/tools.ts를 캔버스 도구에서 다시 쓴다
```

데이터는 `~/.duet/`에 있다: `sessions/`(대화 로그), `canvas/`(지도와 기록), `reviews/`(리뷰 코멘트), `workspaces.json`, `token`, `server.log`.

## 터미널에서 (Duet mod)

`mod/`는 Claude Code mod다. 터미널의 Claude Code 세션이 Duet 지도를 만들고 읽고 고치고, Duet에서 보낸 것을 받는다. Duet은 그대로 돈다.

```bash
claude --plugin-dir ~/github/duet/mod     # 이 세션에만
```

늘 켜 두려면 다른 로컬 플러그인처럼 `~/.claude/local-plugins/duet` → `~/github/duet/mod` 심링크를 만들고 `CLAUDE_CODE_PLUGIN_DIRS`에 더한다. Claude Code 2.1.287 이상이 필요하다.

- **도구.** `duet_map_list`, `duet_map_read`, `duet_map_create`, `duet_map_update`, `duet_map_reply`. Duet 대화의 `canvas_*` 도구와 설명·스키마가 같고(`npm run mod:tools`로 다시 쓰고, 테스트가 어긋남을 잡는다), 서버의 같은 코드로 돈다. 터미널이 만들거나 고친 rev는 에이전트 것으로 남고 메모 앞에 `터미널 · <폴더> · <세션 id 8자>`가 붙는다. 터미널에는 MCP 서버 지시가 없어서, 지도를 그리는 법은 `duet_map_read`와 `duet_map_create`의 결과 앞에 붙는다.
- **지도 만들기.** `duet_map_create`는 빈 지도를 만들고, 모델은 결과에 붙은 그리는 법을 읽고 바로 `duet_map_update`로 그린다. 폴더가 어느 작업 공간에도 없으면 먼저 그 폴더의 git 저장소를 작업 공간 메뉴에서 연 것처럼 Duet 작업 공간으로 열고, 터미널을 거기에 등록한 뒤 만든다. git 저장소 밖이면 git 저장소가 필요하다고 답하고 아무것도 열지 않는다. 다른 도구는 작업 공간 밖에서 그대로 거절하고, `duet_map_create`로 시작할 수 있다고 알린다.
- **보내기.** 세션은 cwd가 속한 작업 공간(그 폴더를 품은 작업 공간, 아니면 그 저장소에 쓴 대화나 그 저장소를 가리키는 지도가 있는 작업 공간)에 터미널로 등록된다. 에이전트 패널의 대화 메뉴 '터미널'에서 고르면 캔버스 코멘트, 알림을 켠 결정, 리뷰 코멘트, 입력창에 쓴 말이 Duet 대화가 받을 바로 그 프롬프트로 그 세션에 간다. 세션이 쉬고 있으면 바로, 일하는 중이면 끝난 뒤 한 턴으로 돈다. 스레드에는 대기열 → 터미널에 전달함 → 작업 중 → 답함이 보이고, 그 턴의 답이 스레드에 달린다. 닫힌 터미널로 보내면 실패하고 토스트로 알린다.
- **연결(`/duet`).** 세션은 Duet에 붙지 않은 채 시작한다: 폴링도, `duet_map_*` 도구도, 상태 줄도 없다. `/duet`(또는 `/duet <지도>`)을 쳐야 그 터미널이 Duet에 등록되고 도구가 생기며 폴링이 돈다. `/duet off`는 고정을 풀고 연결을 끊는다(Duet 터미널 목록에서 빠지고 상태 줄이 사라진다). `/duet new <이름> [제목]`은 모델 턴 없이 빈 지도를 만든다: 다이어그램 종류(class·sequence)를 물어보고, 만든 지도를 이 터미널에 고정한다. 제목을 안 적으면 이름이 제목이 되고, 대화창을 닫으면 아무것도 만들지 않는다. 그래서 `new`라는 이름의 지도는 `/duet new`로 고정할 수 없다. 이미 등록된 도구는 남지만 다시 연결할 때까지 거절한다.
- **기준 지도(`/duet`).** `/duet <지도>`는 이 터미널이 기준으로 삼을 지도를 고정한다. 지도 이름과 똑같으면 그 지도, 아니면 이름이나 제목에 그 글자가 든 지도가 하나뿐일 때 그 지도다(대소문자 무시). 여럿이거나 없으면 후보(이름 · 제목)를 보여 주고 아무것도 바꾸지 않는다. `/duet`만 치면 고정된 지도(없으면 `고정된 지도 없음`)와 작업 공간의 지도 목록(이름 · 제목 · rev, 결정이 있는 지도는 결정 a/b)을, `/duet off`는 고정을 풀고 연결을 끊는다. 고정은 그 터미널(프로세스)에만 있다: 같은 폴더라도 새 세션은 고정 없이, 연결 없이 시작한다(`/clear` 뒤에는 이어진다). 지도가 지워지면 고정도 풀린다. 고정이 바뀌면 모델은 턴을 새로 열지 않고 듣는다: `/duet`의 답에 붙은 숨은 메모(`command.run`의 `context`)로, `/clear` 뒤에는 보이지 않는 user 행(`$.session.append`)으로. 대화를 압축하면(`/compact`, 자동 압축) 요약이 그 메모를 빠뜨릴 수 있어서, 턴이 시작될 때 모델이 받는 메시지(`$.session.messages({ as: 'api' })`)에 메모가 없으면 같은 행으로 다시 듣는다. `session.compact` 훅은 쓰지 않는다: Team·Enterprise 조직 계정이나 managed settings가 있는 기기에서는 Claude Code 내장 플러그인 `cc-plugin-sec-default`가 가장 바깥에 앉아서, 이 이벤트를 사용자가 설치한 플러그인을 건너 넘긴다. 그래서 이 훅은 돌지 않고 /plugins의 Errors에 올라간다. 관리자가 managed settings의 `prependPlugins`에서 그 플러그인을 빼지 않는 한 사용자가 끌 수 없다. 그래서 지도를 말하지 않은 "이 터미널의 지도"는 `duet_map_*` 도구에 고정된 이름으로 간다. 고정된 지도가 없는 터미널이 `duet_map_create`로 지도를 만들면 `/duet <지도>`처럼 그 지도가 고정되고, 모델은 그 도구 결과로 듣는다. 이미 고정된 지도가 있으면 그대로 두고, 새 지도는 마지막으로 만진 지도가 된다. Duet의 터미널 목록에도 `map`으로 올라가서, 에이전트 패널의 터미널 카드에 `기준 지도: <제목>`이 보이고 대화 메뉴에서 그 터미널을 고르면 캔버스가 그 지도를 연다.
- **상태 줄.** `Duet · <지도 제목> · rev N · 결정 a/b · 코멘트 n`. 터미널에서는 프롬프트 아래 힌트 줄(`? for shortcuts`) 끝에 흐리게 붙는다(`$.ui.status`로 띄우면 Claude Code가 ⚠ 알림처럼 그려서다). 터미널이 없는 세션(SDK, `-p`)에서는 플러그인 상태 줄(`ui.status`)로 나온다. 고정한 지도가 있으면 늘 그 지도이고 제목 앞에 📌가 붙는다(`Duet · 📌 <지도 제목> · …`). 없으면 이 터미널이 마지막으로 읽거나 고친 지도, 그 뒤에 다른 지도가 바뀌었으면 그 지도. 서버가 없으면 `Duet 꺼짐`, 작업 공간을 못 찾으면 `Duet 작업 공간 없음`이고(`duet_map_create`로 지도를 만들면 그 저장소가 작업 공간이 된다), 서버가 돌아오면 스스로 다시 붙는다.
- **연결.** `$DUET_HOME`(없으면 `~/.duet`)의 `server.json`과 `token`(또는 `DUET_TOKEN`)을 읽는다. mod는 SSE를 읽을 수 없어서(`$.http.fetch`는 본문이 끝나야 돌아온다) `GET /api/terminals/:id/poll`을 길게 붙잡는다. 이 poll이 heartbeat이고, 메시지와 지도 변경을 받는 길이다.
- Duet이 띄우는 대화에는 이 mod가 붙지 않는다(`CLAUDE_CODE_PLUGIN_DIRS`에서 빼고, `DUET_CONVERSATION=1`이면 아무것도 안 한다).
- `npm run typecheck`는 `mod/.claude-plugin/types/`를 읽는다. Claude Code가 `--plugin-dir`로 mod를 띄울 때 그 버전의 타입을 거기 쓴다.

## 지켜야 할 것

- 서버는 Bash를 돌리는 에이전트를 부리므로, `127.0.0.1`에만 묶고 토큰 쿠키, Host·Origin 검사를 둔다. CORS는 열지 않는다.
- 리뷰와 스냅샷은 작업 트리, 진짜 인덱스, stash를 건드리지 않는다. "Turns" 비교는 임시 인덱스로 트리 객체만 만든다.
- 권한 모드는 `ask`(편집·명령마다 묻기), `edit`(파일 편집은 바로, 명령은 묻기), `auto`(Claude Code auto: 안전한 작업은 바로, 위험해 보이면 묻기) 중에서 고른다. API나 에이전트가 `plan`이나 `bypass`로 바꾼 대화는 그 이름을 그대로 보여 주지만 고르는 목록에는 없다. 새 대화는 늘 `auto`로 시작하고, 모델과 노력은 마지막으로 고른 값을 이어받는다. 읽기 전용 명령(`ls`, `git status` 등)은 어느 모드에서도 묻지 않는다.
- 상단의 작업 공간 메뉴에서 최근 작업 공간, 이 저장소의 워크트리, 홈 아래 세 단계 안의 저장소를 이름으로 찾아 연다. `~/`부터 입력하면 폴더를 한 단계씩 들어간다(`Tab`).
- 대화는 사용자의 Claude Code 설정(CLAUDE.md, 권한, 플러그인)을 그대로 읽는다. 옛 design-map 플러그인만 뺀다. "Always allow"는 Claude Code 규칙대로 그 저장소의 `.claude/settings.local.json`에 쓴다.
- Duet 대화는 Claude Code 세션이라 `claude --resume <id>`로 터미널에서 이어 갈 수 있다(헤더의 복사 버튼). 같은 세션을 두 곳에서 동시에 쓰지 않는다.

## 개발

```bash
npm run typecheck && npm test && npm run build
DUET_HOME=/tmp/duet-dev npx tsx watch server/main.ts --port 7981
```

`DUET_SETTING_SOURCES=project,local`을 주면 사용자 설정(CLAUDE.md, 훅) 없이 대화를 띄운다. 테스트용이다.
